Method 1 · PC Wi-Fi scanner: copy the exact prompt

Paste this into claude.ai. Generated code can vary; if yours doesn't run, download the tested script below instead.

Download prompt .txt
Act as a network security expert. Write ONE complete Python 3 script named hidden_cam_scanner.py that uses ONLY the Python standard library (no pip install, no nmap, no admin rights). I will run it on my own laptop (Windows, macOS or Linux) while connected to a hotel or Airbnb Wi-Fi, to find possible hidden cameras.

The script must:
1. Find my local IP automatically and scan that /24 network (for example 192.168.1.1 to 254). Also accept a different network as an optional argument, like 10.0.0.0/24.
2. Ping every address in parallel with threads, using the right ping command for each OS (Windows: ping -n 1 -w 1000, macOS: ping -c 1 -W 1000, Linux: ping -c 1 -W 1), with a timeout so it never hangs. Count a host as alive only if the ping output contains "TTL" (any case), and decode command output with errors="ignore".
3. Get each device's MAC address. Linux: read /proc/net/arp (fallback: ip neigh). Windows: parse arp -a (MACs use dashes). macOS: parse arp -an and pad short parts (0:1a becomes 00:1a). Also include devices found in the ARP table even if they did not reply to ping. Skip broadcast and incomplete entries.
4. Match the first 3 bytes of each MAC against a built-in dictionary of camera maker prefixes (Hikvision, Dahua, Ezviz, Imou, Reolink, Wyze, Tuya, Xiaomi, Espressif ESP32 chips used in cheap spy cams). Do not include router brands.
5. On EVERY device found, check camera ports 554, 8554 (RTSP video), 8000, 8899, 34567, 37777 (DVR/camera apps) and 80, 8080 (web) with fast threaded TCP connects (0.5 s timeout).
6. Verdict: RED "POSSIBLE CAMERA" if port 554 or 8554 is open, or a camera maker has any camera port open. YELLOW "CHECK" if only the maker matches, or only a DVR port is open. GREEN "OK" otherwise (port 80 or 8080 alone is normal). Always show the reason.
7. Print a clean table of ALL devices (IP, MAC, Maker, Open ports, Verdict) with colors that also work in Windows PowerShell, then a summary: devices found, suspects, and a reminder that a flag is not proof.
Handle errors gracefully, never crash, and finish in about a minute. Output only the code.

3. Run it on your laptop

  1. Connect to a Wi-Fi network you own or are explicitly allowed to scan. Hotel guest networks may prohibit scanning—check their rules or ask staff.
  2. Install Python 3 from python.org/downloads. On Windows, the current download is Python install manager; if you use the older standalone installer, tick “Add python.exe to PATH.” Mac: use the python.org installer. Linux: Python 3 is commonly installed already; check python3 --version.
  3. Save the script in a folder you can find. If copying Claude's code into Notepad, choose “All files” when saving so the filename ends with .py, not .py.txt.
  4. Windows: open that folder in File Explorer, type powershell in its address bar, press Enter, then run py hidden_cam_scanner.py.
  5. macOS or Linux: open Terminal, cd to the folder holding the script, then run python3 hidden_cam_scanner.py.
  6. For a different subnet, pass it explicitly: python3 hidden_cam_scanner.py 192.168.0.0/24. By default it scans the local /24; large networks and guest isolation can limit visibility.

How to read the result

Each row shows an IP, MAC address, maker, open ports and a verdict. GREEN is no camera-like signal; YELLOW means check manually; RED means a possible camera because an RTSP port (554/8554) is open or a camera-maker device has a camera/DVR port. Red is NOT proof, green is NOT a guarantee. Vendor names can refer to chips used by many ordinary devices.

Check smoke detectors, clocks, chargers, outlets, mirrors and unusual pinholes. In a dark room a flashlight may make a lens glint. A phone camera may show some IR LEDs, but not all.

An offline/SD-card or cellular camera will not appear; hotel client isolation may hide every other device. Do not assume a clear scan means the room is safe. If concerned, leave the room and tell staff or local authorities.

Phone users

This script is for a laptop/PC. We could not verify an end-to-end non-rooted Android/Termux route; Android may block reading other devices' MAC addresses, so we do not advertise it as supported. On a phone, a free network scanner like Fing can show connected devices; check the maker and inspect the room physically. It still cannot rule out offline or isolated cameras.

Download phone prompt .txt
Build me a "Hidden Camera Lens Finder" web app as ONE single self-contained index.html file (all HTML, CSS and JavaScript inside it, no external libraries, no CDN, no build step). It must work in a phone browser (Android Chrome and iPhone Safari) and also on a laptop with a webcam.

What it does (be honest: it is a lens-glint finder, NOT a Wi-Fi scanner and NOT an automatic camera detector):
1. A big "Start Camera" button. On tap, call navigator.mediaDevices.getUserMedia({ video: { facingMode: { ideal: "environment" }, width: { ideal: 1280 }, height: { ideal: 720 } }, audio: false }) to open the REAR camera, and show the live video full width with playsinline, muted and autoplay set (needed on iPhone).
2. Glint detection: about 10-15 times per second, draw the video frame onto a small hidden canvas (around 320 px wide), and find tiny, very bright spots that are much brighter than their surroundings. For each pixel use brightness = max(R,G,B). A pixel is a candidate if brightness >= a "Sensitivity" threshold (slider 150-255, default 230) AND it is at least 60 brighter than the average of a ring of pixels about 6 px away. Group candidate pixels into blobs (simple flood fill or grid clustering). Keep only SMALL blobs (1 to about 40 pixels at the 320 px scale) so big lamps, windows and screens are ignored. If more than 20% of the frame is very bright, show a small hint "Too much light: dim the room or step back", but keep detecting small spots (a flashlight hotspot on a wall must not switch detection off).
3. Draw a red box (with a small label "check") on an overlay canvas exactly over each detected spot, scaled correctly to the displayed video size (handle object-fit and screen rotation). Show a counter "Bright pinpoints: N".
4. A spot that stays in nearly the same place for 5+ frames in a row gets a thicker red box. When that happens, optionally beep (Web Audio API, short beep, max once per second) and vibrate (navigator.vibrate(100) only if it exists). Add Sound and Vibrate on/off toggles (off by default; Web Audio must be started from a user tap).
5. Flashlight: after the camera starts, get the video track and check track.getCapabilities && track.getCapabilities().torch (browsers report it as true or as an array like [true, false], so treat it as supported if it is true or an array containing true). ONLY if supported, show a "Flashlight" toggle that uses track.applyConstraints({ advanced: [{ torch: true/false }] }). If torch is not supported (iPhone Safari, most laptops, many phones), hide the toggle and show this tip instead: "Your browser can't control the flashlight here. Turn on a second phone's flashlight or any torch, hold it right next to this camera, and point both at the object."
6. A "Switch camera" button (toggle facingMode between environment and user, stop the old tracks first) and a "Freeze / Resume" button.
7. Clear error messages for every failure: no navigator.mediaDevices (say: "Camera needs a secure page. Open this file from an https:// link, not from a downloaded file or http://"), NotAllowedError (permission denied: explain how to allow camera in browser settings), NotFoundError (no camera), NotReadableError (camera busy in another app). Also check window.isSecureContext at load and show a warning banner if false.
8. "How to scan" panel (collapsible): turn off room lights or close curtains, turn on the flashlight, hold the phone at eye level and move slowly around the room; a hidden camera lens often shows a small, steady bright reflection that stays in the same spot as you move a little. Checklist with checkboxes: smoke detector, wall clock, USB charger / adapter, mirror / glass panels (in a dark room, hold the flashlight close to the glass and look for a pinhole or lens glint behind it), AC vent, plant / decor, TV / set-top box, alarm clock, power socket, photo frames, bathroom fittings.
9. "Night-vision (IR) tip": in a dark room, look through the phone's FRONT camera (selfie camera) at suspicious spots; some night-vision cameras show a faint purple/white glow. Caveat: many phones' rear cameras block IR, some front cameras do too, and many hidden cameras have no IR light, so no glow does not mean safe.
10. An always-visible honest note: "A red box means a bright reflection, not proof of a camera. Metal screws, glass, water drops and LEDs can also shine. Many hidden cameras have tiny or covered lenses and will not show. This app cannot identify cameras automatically. If you find something, do not touch it, take a photo, and tell hotel staff or police (India: 112)."

Design: mobile-first, dark theme, large touch buttons (min 48 px), works in portrait and landscape (in landscape put the camera view beside the controls so the whole camera view is visible without scrolling), no horizontal scrolling.

Self-check before you answer: a single 3 px white dot on a dark frame must get exactly 1 red box exactly on it; a 60x60 px white square (a lamp or window) on a dark frame must get 0 boxes, including at its corners and edges; a plain dark frame must get 0 boxes. All processing stays on the device: no uploads, no network requests, no tracking.

Also tell me in 3 short lines how to open it on my phone: camera access only works on an https:// page (or localhost), so upload the file to a free static host (for example Netlify Drop or GitHub Pages) and open that https link. Opening the downloaded file directly may block the camera.

Give me the complete index.html in one code block, no placeholders, no "rest of code here".
